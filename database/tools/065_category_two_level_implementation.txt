STOCKFLOW TWO-LEVEL CATEGORY IMPLEMENTATION - 30 OCTOBER 2026

Architecture and screens
Parent Category -> optional Subcategory -> Products -> Variants -> Inventory.
Category IDs and codes remain the identity used by existing modules.
/Categories: expandable two-level list, direct/subtree product counts, search,
parent/status filters, 25-parent pagination, empty states and More Actions menu.
/Categories/Create?kind=parent: create a top-level category.
/Categories/Create?kind=subcategory&parentId=<id>: create under an active root.
/Categories/Edit?id=<id> and /Categories/View?id=<id>: existing registration
routes retain identities; parent relationships are read-only during editing.
Product registration exposes required Parent Category and optional Subcategory;
the selected existing ID is stored. No third selector or replacement categories.
Existing charcoal/pink action styling and responsive grids are retained.

Backend
Create/update/import database paths reject third-level categories, invalid parents,
cross-shop relationships and normalized duplicate sibling/root names.
Existing parent relationships cannot be silently moved through ordinary edits.
POST /api/categories/{id}/status uses the existing DEACTIVATE permission.
Parent deactivation preserves independent child flags, while preventing new
assignments to the parent or its children. Reactivation preserves inactive children.
Existing product assignments can still be edited without changing their category.
Brand deactivation safeguards remain in place. Retired wrappers remain available
for direct historical lookup but are excluded from normal category lists.
