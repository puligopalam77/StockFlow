Specialist workflows — first implementation increment, 2026-11-02

Scope
Uses the existing 62-workflow audit, rather than repeating it. This increment
prioritizes verified reporting defects, transaction/variant safety verification,
small keyboard/scanner corrections, and benchmark/pilot preparation. It is not a
claim that every phase of the specialist brief has been delivered.

Delivered report corrections (F06)
OperationsRepository.ProductSalesAsync now uses original saved line amounts and
tax-exclusive bases. Modern allocated invoice discounts remain in the saved line
base; legacy saved after-tax allowances are allocated proportionally using
cumulative rounding, once only. Report sales follow invoice date, returns follow
return date, and collection/refund events do not create product revenue.
Return-only catalog and manual rows remain visible, including negative net
quantity. Returns use their saved amount and original line-tax proportion. This
does not rewrite original invoices or create statutory GST credit notes.

The existing received-price-average management estimate is retained using receipt
price/discount snapshots in the original sale's location, both received and
recorded before that sale. Future receipts, including later-recorded backdated
receipts, cannot reprice it. There is no fallback to an all-time current purchase
price or zero when evidence is absent. Manual costs remain unknown. Nonpositive
raw purchase-price evidence is treated conservatively as unknown. If any event in
a product row lacks evidence, that row's estimated cost/profit stays unknown.

This is a price-history estimate, NOT a selected FIFO/weighted-average inventory
costing policy, authoritative COGS, valuation ledger or net profit. Available
receipt-price evidence does not establish actual acquisition cost for every sold
unit. Opening/direct-intake/transfer costs, landed costs and prospective cost
adjustments remain F05 work requiring explicit policy/migration decisions.
Subsequent source corrections/reversals can affect evidence; no immutable cost
posting or historical backfill is claimed by this increment.

The report labels tax-exclusive sales and estimated gross profit, shows actual
SKU, marks unknown rows and partial totals, and displays Unknown rather than zero
when every row lacks a cost estimate. Its API additionally requires SALES VIEW
alongside REPORTS VIEW; source RLS remains authoritative. API route unchanged:
GET /api/operations/reports/product-sales. Sku is additive; manual aggregate
ProductId/VariantId are now explicitly nullable rather than fabricated zero IDs.

Checkout refinements and safety
Existing request identities, finalization transaction, verification-only recovery,
discount policy and payment rules are reused. No new posting engine or balance
calculator. A refreshed pending checkout now says unconfirmed/verification rather
than presenting every saved request as an older billing draft.
Scanner held-key/modifier Enter events cannot add items; a real repeated scan can
still intentionally increment quantity. Search-result Enter also ignores key
repeat. Arrow/Escape/customer navigation remain in the existing implementation.
Global Alt shortcuts ignore typing, composition, repeats, Ctrl/Meta combinations
and native/Bootstrap dialogs. Alt+S search, Alt+C customer, Alt+P payment, Alt+H
hold; Alt+B focuses the checkout button and does not submit. A selected customer
is focused via the existing Clear Customer control without clearing it.
Discoverability uses a compact, closed Keyboard shortcuts disclosure.

   service records with source permissions on every link. A unified chronological
   history UI and its cross-shop/privacy tests are NOT delivered in this increment.
2. Stock explanation: extend the existing history screen using the existing signed
   movement/report sources for opening/inflows/outflows/closing, source/user/reason
   and reliable running balances. No replacement ledger or fabricated movements.
3. Remaining lifecycle verification: purchase/partial/damaged receipts, transfer,
   count, manufacturer-part search/verified vehicle fitment, every supported profile
   and same/different-profile shop combinations need their slice's tests. Existing
   suites are not labeled passed here merely because they are present.
4. Quotations remains the implemented first module; Expenses remains its separately
   planned next vertical slice. This brief does not authorize choosing a costing
   policy or replacing the F05 financial-correctness roadmap.
5. Run the documented competitor tasks and owner-supervised live pilot only with
   authorized accounts/devices/data. Set targets from measured baselines.

Release limits
Actual production two-shop topology and strict shop-master isolation remain release
gates. Existing tenant/profile-shared masters are not repartitioned. Genuine
hardware, isolated restore acceptance and broader financial reconciliation remain
the existing production gates. No unsafe offline finalization or new split/credit
checkout enabled. No SQL migration or application/production data changes.
