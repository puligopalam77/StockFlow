Table
Product/Variant | Available Stock | Qty | Unit Price | Item Discount | Tax (%) |
Line Total | Actions.
Unit price and line discount now remain directly visible; tax is a read-only
server quote value. Numeric editors have consistent sizing and right alignment.
The same editors and cart state are used at every screen size. Desktop/tablet
use a compact table with controlled horizontal scrolling if space is limited.
Mobile uses stacked item cards with directly accessible price, discount, stock,
quantity, tax, total and removal controls; the page does not scroll sideways.
Images use the existing registered-image endpoint or neutral package fallback.
The product cell shows the first two identifying attribute values and a separate
muted SKU. Full attributes, serial/unit identifiers, model and warranty context
remain available in a compact More Details disclosure when relevant. These
fields do not automatically expand when More Billing Options opens.
Remove retains its existing handler and has a Remove Item tooltip.

Behavior and safeguards
- Price editing follows the existing canOverridePrice permission immediately;
  it no longer requires opening a separate options panel.
- Discount editing follows the existing canDiscount permission.
- A discount is one amount for the entire line, never multiplied by quantity.
- The existing quote endpoint remains the pricing/tax/rounding authority.
  No new UI calculator, pricing state or tax selector was introduced.
- Invalid negative/over-value discounts show inline feedback and disable
  completion; backend SaleRules independently enforces the same value boundary.
- Adjusted rows show a compact reason/approval notice. The existing reason field,
  policy thresholds, approval request/status and server fingerprint checks remain.
  This notice does not claim that a bill has already received approval.
- Quantity rules, repeated scanning, unit duplication checks, stock checks,
  physical-unit quantity locks, final stock revalidation and idempotent posting
  remain in the existing sale workflow.
- Draft edits/removal only update local/server drafts and quotes. They do not
  call sale finalization or change product catalog selling prices/history.
