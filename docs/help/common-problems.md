# Common problems

Use the message beside the field or at the top of the screen to identify what needs attention. If a save may already have succeeded, check its result before starting a duplicate transaction.

| Problem | What to do |
| --- | --- |
| A required field is empty | Complete the fields marked **\*** and those identified by validation messages, then submit again. |
| A mobile number is rejected | Enter exactly ten digits, with no country code, spaces or letters. Leave optional mobile fields empty when no number is available. |
| The scanner does not enter a code | Click the screen's scan box first. Try typing the same code and pressing Enter. Ask the administrator to check the scanner's keyboard input and Enter suffix if typing works but scanning does not. |
| The product code is not registered | In **Receive new stock**, use **Add new product** if authorized. In billing, find the existing product or ask an authorized person to register and receive it before sale. |
| A serial is rejected | Check for duplicates, confirm the physical item's serial, and keep it within 150 characters when receiving. Enter one serial for each good or damaged item. |
| Received quantity is rejected | Check **Received (good)** plus **Damaged** does not exceed **Expected quantity**. Use whole numbers. |
| An item cannot be sold | Check that stock is available at the assigned location. For a serialized item, use the available physical unit's serial. Ask the responsible person to review stock rather than changing the quantity to bypass the message. |
| Credit is rejected | New Sale requires full payment by one collected method. New credit/pay-later is unavailable; authorized collections on older credit invoices remain supported. |
| Split payments are rejected | New split checkout is unavailable. Choose one method covering the total. Historical split allocations remain readable. |
| A refund is rejected | Check remaining return quantity, prior refunds and payments received. Use the appropriate settlement; see [Returns](returns.md). |
| A screen or button is missing | Ask the administrator to check your role and permissions. |
| The application asks you to sign in again | Sign in and check any pending transaction or saved draft before resubmitting. |

## A receipt save has an uncertain result

Use **Retry saved receipt** to retry the saved request. Use **Check purchase history** to inspect whether the receipt was recorded. Select **I checked history; start a new order** only after checking the previous result and deciding to start another order.

## A sale save has an uncertain result

Use **Retry saved sale** without changing its items or payment. Check for the completed invoice before starting another bill. Do not collect payment again merely because the screen did not show confirmation.

## Sign in fails

For **Invalid username or password.**, check the username and password, including letter case. For **Your account is inactive. Please contact your administrator.**, contact the administrator to review the account.

**Forgot Password?** opens the new-password form and carries the username entered on the login page. Account verification is still required to save a new password; contact the StockFlow administrator for recovery.

## Contact the administrator

Provide the screen name, exact error message, time of the problem and relevant invoice or product code. Share only the details needed to investigate. Never share passwords.
