# Login and dashboard visual refresh

## Professional retail UI standard

Use this instruction for future screen refinements: "Refine this screen using StockFlow's existing professional retail UI standards. Preserve the current theme, functionality, and architecture. Improve only spacing, alignment, typography hierarchy, component consistency, and usability. Avoid generic AI-style layouts, unnecessary cards, decorative elements, and visual clutter."

Home dashboard exception: `dashboard-business.css` owns its content-aware banner and local section spacing. Keep every welcome/slogan/statistic element visible at every screen width. Normal desktop banner height is about 242px; allow tablet/mobile and long content to grow. Banner statistics and Quick Actions reflow without hiding authorized content. Use 12px banner-to-actions, 14px actions-to-overview and 10px overview-to-cards gaps. Do not transfer these promotional heading/layout rules into ordinary module pages. See `docs/dashboard-compact.txt` for measured before/after results and coverage.

Compact typography/header standard: authenticated page titles are 22px, weight 650, line-height 1.25; subtitles 13px, breadcrumbs 12px, section headings 16px, card headings 14-15px and labels 12-13px. Preserve the font family. Shared header groups use 12px bottom spacing and wrapping actions. Standard/header buttons use 36px targets, compact buttons 32px and primary workflow buttons 40px. Inputs retain their independent 38px minimum; POS lookup actions retain 38px, checkout/payment confirmation 44px, and mobile/coarse-pointer actions 44px. These sizes are content minimums: allow labels to wrap and controls to grow instead of clipping them. Do not proportionally scale the page or reduce customer/barcode entry controls to match header buttons.

Sizing ownership remains in `retail-usability.css`: the existing control-size layer owns minimums and the single title-size declaration handles legacy important page rules. Header actions set their own button size token; they do not pass smaller dimensions into the billing workspace. `list-screens.css` reuses the shared page-title token; `breadcrumbs.css` owns compact breadcrumb spacing. Keep colors and button semantics in `button-theme.css`. Exclude login/authentication, dashboard promotional headings, KPI micro-labels, invoice/document branding and printed output from page typography rules. Confirmation dialog hierarchy and critical controls remain distinct from ordinary card headings. Do not change billing columns, form validation or workflows for typography refinements.

Operating Expenses established the reference implementation across list, creation, details, and reports screens. The same standard now lives in the shared retail, operational, and action styles used throughout StockFlow, including product registration, catalogue lists, purchases, sales, inventory, reports, settings, and administration. Keep the shared sidebar, header, logo, font stack, navy text, and magenta primary actions. Reuse existing theme variables and controls; do not introduce a parallel theme:

- Group related content with subtle borders and content-driven heights. Use 16px form/report card padding, 12–16px field and section gaps, and the existing compact list spacing.
- Use magenta for the primary action, neutral outlines for secondary actions, and links for tertiary navigation. Retain existing destructive styles, focus indicators, permission checks, and loading/disabled behavior.
- Align labels and controls. Bound short report date fields on desktop; stack fields on narrow screens. Keep entry fields at least 38px high on desktop and 44px on phones; use the action sizes above without enlarging checkbox/radio inputs or compact row actions.
- Right-align monetary columns and their headings with tabular numerals. Keep table overflow inside its scroll container.
- Use consistent expense dialog headers, footers, 12px corners, and restrained headings. Preserve native dialog focus containment, Escape handling, validation, and existing selector behavior.
- Preserve GST, ITC, payment, confirmation, and reporting-scope explanations. Visual cleanup must not alter calculations, APIs, persistence, permissions, or navigation guards.

Shared implementation: `retail-usability.css` owns control sizes and small module corrections; `operational-screens.css` owns operational section density; `button-theme.css` owns semantic primary/secondary action colors. Keep compact row icons on `action-icons.css` and list density on `list-screens.css`. The StockBot launcher has its own place below content, with its existing dialog and event handlers, so it cannot cover form actions or report values. It is no longer a floating overlay in the shared layout. Expenses retain their existing local assistant dock.

Product Import and Bulk Update currently have no rendered route or `catalog-tools` host in this checkout. Their retained JavaScript is not a live workflow; do not create or enable those features as part of visual refinement. Any future screen should reuse the shared controls and hierarchy.

Keep before/after captures and results in `.artifacts/application-ui-standard/`.

## Existing shell and dashboard

The interface follows the supplied black/navy and pink references with live HTML forms, a responsive sidebar, KPI cards, charts, and stock activity tables. Desktop uses a split login and fixed sidebar; tablets and phones use a collapsible navigation drawer and reflowed cards. No database migrations are required.

Dashboard values are read from existing products, suppliers, customers, and inventory movements in a consistent read-only snapshot. Empty data is shown as zero/empty state, not the reference image's sample figures. Supplier counts and names are limited to Admin. Inventory and Admin stock adjustments are available from the sidebar. Admin and Sales can open sales/invoices and new sale/dispatch. Admin can edit company/invoice settings; printable invoices are available to Admin, Sales and Service. Forgot password provides administrator contact guidance rather than pretending to send a reset email.

Final shared navigation standard (8 November 2026): freeze the sidebar's visual design at a 230px desktop width, 72px brand header, 44px parent rows, 18px icons, 14px parent text, 12px horizontal row padding and compact 4px row gaps. Submenus use consistent 24-25px indentation per level. Desktop child links use 36-40px rows and 13px text; mobile children retain 44px touch targets and the existing drawer. `stockflow.css` owns the single `--sf-sidebar` layout token and mobile breakpoint; `shop-navigation.css` owns compact navigation presentation. Reuse these conventions when refining remaining screens, alongside the control/section spacing and button standards above. Do not repeatedly restyle navigation or create page-specific sidebar width overrides. Change it only for an explicit new requirement or a demonstrated accessibility/layout defect. Preserve the current dashboard composition, use industry-neutral hardcoded helper text, and retain store-provided business data and profile-specific workflows.
