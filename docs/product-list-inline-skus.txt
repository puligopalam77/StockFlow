Result
Authorized product-management lists show Product Name, Product Code, SKU,
Category, Brand, Variants, Status and Actions. Existing role rules still omit
unauthorized write actions. Model, HSN, sold-as, GST, tracking and warranty fields
remain in saved records, APIs and registration/edit forms. Only list columns
were simplified; Product Code, SKU generation and financial behavior are unchanged.

A simple product shows its actual saved default SKU, or Not assigned. Configured
products initially show one saved SKU, with +N more SKUs only when N > 0. The
initial repository query now limits SKU previews to one, preserving existing
counts and deterministic variant-ID ordering. During a SKU search, a matching
saved SKU takes priority; clearing search restores the established order.

The pink text disclosure is a real keyboard-accessible button with a product
name, aria-expanded and aria-controls. Expansion stays inside the same cell and
parent row; additional entries use their saved SKU and variant name. Show less
collapses the entries. There are no nested tables, extra rows, drawers or modals.
The existing compact action component is unchanged.

Data loading and state
The existing GET /api/products/{id}/skus endpoint is reused without API changes.
It pages up to 100 entries and already restricts results by authenticated tenant,
visible shop profile and product ID. No detail requests occur during list load.
Duplicate pending requests are blocked, returned entries are deduplicated against
the preview, and large collections expose Load more SKUs. Loading/error messages
stay in the cell with a Try again control. Entered search/filter state and other
rows are retained on failure. Read-only access can inspect SKUs without gaining
edit permission.

Caches are keyed by product ID within the current list generation/scope and
cleared on list refresh. Removed rows and stale search/shop responses cannot
append data. Current-shop metadata changes abort requests and clear SKU cells.
Existing shop switching reloads the page. Back/forward restoration refreshes
the list using the existing search/filter controls instead of stale SKU caches.

Responsive styling
The list minimum width is reduced from 76rem to 48rem; horizontal scrolling
remains available on narrow screens. Identifiers stay intact. Disclosure buttons
have transparent backgrounds, pink text and a visible focus outline; coarse
primary pointers receive 44px disclosure targets. Row heights grow naturally
only when their content requires it.
